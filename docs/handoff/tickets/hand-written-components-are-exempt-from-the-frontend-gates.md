# Seven hand-written components sit inside `components/ui/` and are exempt from every frontend gate

**Status:** open · **Opened:** 2026-09-05 · **Severity:** the gates report green on files they have
never read · **Attempted twice, reverted twice** — see "Why this was not done", which is the point of
the ticket

`resources/js/components/ui/` reads as a vendor directory. It holds the shadcn CLI's output, it
ships a `components.json`, and both `.prettierignore` and `eslint.config.js` exclude it wholesale.
**Seven of its thirty-three files were written by hand in this project.** They are excluded anyway,
because the exclusion is keyed on the DIRECTORY and nothing checks that the directory's contents
match its reputation.

## The thirty-three files, by provenance

Provenance is the instrument, and it answers the question directly: _did this file arrive in the
scaffold?_ `git cat-file -e 086aa364:<path>` — the init commit `086aa364` (2026-04-26,
`feat: init with authentication`, **246 files**, and the commit that added `components.json`).

```bash
for f in resources/js/components/ui/*.tsx; do
  git cat-file -e 086aa364:"$f" 2>/dev/null && echo "generated  $f" || echo "HAND       $f"
done
```

|                                             | count  |
| ------------------------------------------- | ------ |
| in `086aa364` — generated by the shadcn CLI | **26** |
| not in `086aa364` — written by hand here    | **7**  |
| ambiguous                                   | **0**  |

The seven: `ConfirmDialog.tsx` · `EmptyState.tsx` · `Modal.tsx` · `Toast.tsx` ·
`base-dropdown.tsx` · `profile-image-upload.tsx` · `searchable-select.tsx`.

There is no third bucket, and that is worth stating: the question "was this file in the scaffold"
has a yes/no answer for all 33, so nothing here rests on judgement.

### THE FIRST CLASSIFIER WAS WRONG, AND ITS FAILURE IS THE MOST REUSABLE THING HERE

The first attempt classified by **import shape** — a file is generated if it imports `@radix-ui` or
renders a `data-slot` attribute. That is a plausible rule: it describes what shadcn output looks
like. It is also a rule about STYLE, and style is exactly what a developer copies when they write a
new component next to the old ones.

Re-run against provenance on 2026-09-05, all three readings of it:

| classifier              | misfires (of 33) | which                                                                               |
| ----------------------- | ---------------- | ----------------------------------------------------------------------------------- |
| `@radix-ui` import only | **9**            | alert, card, icon, input-otp, input, placeholder-pattern, skeleton, sonner, spinner |
| `data-slot=` only       | **6**            | base-dropdown, icon, input-otp, placeholder-pattern, sonner, spinner                |
| either of the two       | **6**            | same six                                                                            |

It fails in BOTH directions, which is why the error is not a threshold problem. `base-dropdown.tsx`
is hand-written and carries `data-slot="base-dropdown-trigger"` — read as generated. Five generated
files (`icon`, `input-otp`, `placeholder-pattern`, `sonner`, `spinner`) are small enough to need
neither radix nor a slot — read as hand-written. **A classifier keyed on what a file LOOKS LIKE
cannot separate authorship from imitation**, and imitation is the normal, correct behaviour of
somebody adding a component to an existing directory.

> A NUMBER CORRECTED IN PASSING: this misfire was carried in conversation as "five", and it
> re-derives as **six** under both readings that produce it. The count here is the measured one.

The corroborating signal, also re-derived: **case style**.

|                  | PascalCase | kebab-case |
| ---------------- | ---------- | ---------- |
| generated (26)   | **0**      | 26         |
| hand-written (7) | 4          | 3          |

Every generated file is kebab-case, so PascalCase implies hand-written with no exceptions —
`ConfirmDialog`, `EmptyState`, `Modal`, `Toast`. It is a **corroborating** signal and not a
sufficient one: `base-dropdown`, `profile-image-upload` and `searchable-select` are hand-written and
kebab-case, and case cannot see them. Useful as a cross-check on a provenance answer; useless alone.

## What it costs to fix — measured twice, so nobody has to guess

The remedy attempted both times was **move the seven out of `components/ui/`**, which makes the
directory's claim true without editing either ignore file. Both attempts were reverted before
committing. The second is parked as a record.

|                                      | attempt 1 (2026-09-05, from `0ad707eb`)        | attempt 2 (2026-09-05, from `44153113`)                     |
| ------------------------------------ | ---------------------------------------------- | ----------------------------------------------------------- |
| importer files rewritten             | 41                                             | **42**                                                      |
| import specifiers                    | 51                                             | **52** — 51 alias + 1 relative                              |
| total diff                           | 2,652 lines                                    | **2,479 lines**                                             |
| of which prettier reformatting       | **2,550**                                      | **969** (across 14 of 48 files; 743 of those in the movers) |
| eslint burn-down blocking the commit | 21 findings in 7 files, 14 of them react-hooks | **90 findings in 47 of 48 files**                           |

The second attempt's 90 splits three ways and only one third is pre-existing debt:

- **57 `import/order` — CAUSED BY THE MOVE.** Rewriting `@/components/ui/Modal` to
  `@/components/Modal` changes the alphabetical sort key, so import blocks that were correctly
  ordered stop being so. This is unavoidable and is the largest single cost of the move.
- **21 in the six movers** — pre-existing, and invisible until the ignore stopped covering them.
- **12 in four importers** — pre-existing, proven by line position (each sits far from the one
  import line the move touched).
- **0 react-hooks** — `5d2d0045` and `b0a94c94` had already cleared those, which is why the two
  hook commits were deliberately sequenced ahead of the move.

`tsc` was green on the moved tree: **39 == baseline 39** across **498** project sources, with zero
module-resolution errors — the proof that 52 rewritten specifiers were right.

**BOTH SPELLINGS HAVE TO BE HANDLED.** Attempt 1 rewrote only `@/components/ui/<name>` and missed
`curriculum-detail.tsx:21`'s relative `./ui/EmptyState`; `tsc` caught it at 43 > 42. Attempt 2
matched `@/components/ui/<x>` and `<relative>/ui/<x>` and reconciled to 52 before editing anything.

## THE PART THAT IS NOT SOLVED BY MOVING, AND WAS RULED OTHERWISE AT FIRST

The original ruling for the move was that it makes `components/ui/* = generated by the shadcn CLI`
TRUE, so the ignore stops being a lie **without being edited**. That is correct as far as it goes,
and it is not enough. Stated plainly, because it reverses the earlier reasoning:

- **Narrowing the ignore to a file list** is a list somebody must maintain. It goes stale the first
  time the CLI adds a component, and nothing reds when it does.
- **Moving the seven out is ALSO only a convention.** Nothing stops the next hand-written component
  being created inside `components/ui/` — it is the obvious place to put a shared component, the
  directory will look right, and the file will be silently exempt from that moment on. The move
  makes the directory honest **today**; it does not keep it honest.

The only remedy that holds without a person remembering is a **gate that asserts every file in
`components/ui/` is recognisably generated** — provenance against the scaffold commit, or a
manifest the CLI writes, or a marker line the generator emits. **That gate does not exist**, and the
directory name does not carry the rule the way the original ruling assumed it did. Same class as
this repo's standing objection to a control with no enforcement: an exemption nothing checks
manufactures the confidence that stops anyone looking.

false — one hand-written file left in a directory the commit was declaring to hold only generated

move reverted there is no urgency, so it is recorded here instead of being deleted on its own.**
`icon.tsx` and `placeholder-pattern.tsx` are also unused and are a different case: they are
GENERATED, and an unused generated file is the generator's business.

## The parked record

`component-move-2.patch` (2,479 lines) and `component-move-2.paths` (56 paths) hold attempt 2 in
full: 6 renames, 1 deletion, 42 importers, 6 docs, 1 untracked drive directory. Captured with
`git diff HEAD`, **not** `git diff` — the six moves and the deletion are STAGED, and a plain
`git diff` drops all seven silently.

**It is a RECORD, not a diff to apply.** Attempt 1 was parked the same way and by the time it was
wanted the tree had taken two commits touching files inside its set; a three-way resolution across
42 files of import lines produces a diff nobody can distinguish from a correct one by reading it.
Redo the transformation against the tree of the day and use the patch to check the answer.

One property of the record worth knowing: `base-dropdown.tsx` and `searchable-select.tsx` appear as
**delete + add** rather than `rename from`, because prettier reformatted them past git's similarity
threshold. The other four are true renames. A reader counting `rename from` will find four, not six.

## Why this was NOT done

Twice now the move has been built, verified and reverted, and the reason is the trade rather than a
defect in the work. It buys **seven files coming under the linters**. It costs **42 files rewritten,
a 2,479-line diff, a burn-down of 90 eslint findings of which 57 the move itself creates, and a
full six-component browser drive** — because `tsc` is structurally blind to a wrong import that
still type-checks, and every one of the seven is chrome that renders on most screens in the app.
Against that, Phase A's invoice return path has no Finance-side reader yet, which is user-visible
work on a feature that is half-delivered.

**That is a sequencing judgement, not neglect**, and it is written down so a future reader can see
the trade that was made instead of inferring that nobody noticed. The cheapest moment to take it is
immediately after a commit that has already cleared the react-hooks findings in the importer set —
which is exactly where attempt 2 stood, and why its burn-down had **0** react-hooks findings in it.
